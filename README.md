# Customer Sales Data Cleaning & Visualization

An end-to-end data cleaning and exploratory analysis project in Python. It takes a deliberately messy customer sales dataset (`messy_customer_sales_data.csv`, 10,200 rows) and turns it into an analysis-ready dataset (10,000 unique customers), then visualizes the result.

![Dashboard](charts/00_dashboard.png)

## Dataset

`data/raw/messy_customer_sales_data.csv` holds customer records for an Indian retail business.

| Column | Description | Raw problems |
|---|---|---|
| `Customer_ID` | Customer identifier (`CUST1234`) | ~10% blank, repeated across duplicate rows |
| `Name` | Customer name | Titles/suffixes (`Mr.`, `Dr.`, `MD`, `DVM`, `Jr.`) |
| `Gender` | Male / Female | 8 spellings (`m`, `M `, `MALE`, `female`...), blanks |
| `Age` | Age in years | Stored as text (`"51.0 years"`), blanks, impossible values (`-10`, `3`, `250`) |
| `City` | City of residence | Padding spaces, mixed case, blanks |
| `Signup_Date` | Account creation date | Stored as text |
| `Last_Purchase_Date` | Most recent purchase | Stored as text, blanks, 916 earlier than signup |
| `Purchase_Amount` | Purchase value | Blanks, `-500`, `0`, `9,999,999` |
| `Feedback_Score` | Rating, 1-10 | Blanks |
| `Email` | Email address | Mixed case |
| `Phone_Number` | 10-digit phone | 1,064 lost leading zeros (6-9 digits) |
| `Country` | Country | `India`, `india`, `InDia`, `IND`, blanks |

## Cleaning steps

All steps are in [`src/clean_data.py`](src/clean_data.py).

| # | Task | What was done |
|---|---|---|
| 1 | **Inconsistent formatting** | Trimmed whitespace; standardised Gender, City (Title Case) and Country; stripped name titles/suffixes; lowercased emails |
| 2 | **Data types** | Age to integer; amounts and scores to numeric; dates to `datetime`; phone kept as text and zero-padded to 10 digits |
| 3 | **Duplicates** | 200 duplicate customers found only *after* standardising (matched on phone + email); merged into one row each, keeping the first non-empty value per column |
| 4 | **Outliers** | Age outside 18-90 and Purchase_Amount that is `<= 0` or above the IQR upper fence (~74,443) set to missing (14 and 15 values) |
| 5 | **Missing values** | Age and Purchase_Amount: median. Gender, City: `Unknown`. Country: `India`. Customer_ID: surrogate `UNK0001...`. Feedback_Score and Last_Purchase_Date: left blank on purpose |
| 6 | **Logical checks** | Rows where last purchase is before signup are flagged, not altered |

**Flag columns** in the cleaned file mark values that were filled or are suspicious, so they can be excluded from analysis: `Age_Imputed`, `Purchase_Amount_Imputed`, `Customer_ID_Missing`, `Date_Inconsistent`.

## Visualizations

Generated by [`src/visualize_data.py`](src/visualize_data.py) into [`charts/`](charts/): missing values and outliers before/after, age and purchase distributions, revenue by city, gender split, feedback scores, signups over time, spending by age group, and a correlation matrix.

Observations: spending is spread evenly (median about 24,350), cities are within about 6% of each other in total purchases, and feedback shows essentially no correlation with age or amount. The data looks synthetic, so treat it as a cleaning and charting exercise rather than a source of business conclusions.

```bash

cd customer-sales-data-cleaning
pip install -r requirements.txt

python src/clean_data.py       # writes data/cleaned/cleaned_customer_sales_data.csv

```

## Assumptions and limitations

- Phone numbers shorter than 10 digits are assumed to have lost a leading zero (no real number in the file starts with 0).
- Missing `Customer_ID` values cannot be recovered; placeholder IDs are used and flagged.
- Median imputation for Age and Purchase_Amount keeps the median stable but understates variance; use the flag columns to exclude imputed rows.
- Gender may conflict with the original name title in some rows; this was not corrected.
